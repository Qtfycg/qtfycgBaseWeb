# selectHelp 页面合规修复设计

## 1. 目标

在不改变现有业务流程、信息架构和视觉方向的前提下，按最新版 Web Interface Guidelines 审查并修复当前微信小程序页面的可访问性、触控体验、内容适配和动效降级问题。

规范来源：<https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md>

## 2. 修复范围

覆盖 `miniprogram/pages/` 和 `miniprogram/components/` 中现有 WXML、WXSS，以及为防止重复提交或补充可访问状态而必需的少量 TypeScript 调整。

### 2.1 交互语义

- 简单操作和导航优先使用原生 `button`。
- 保留复杂卡片结构时，增加小程序可访问角色、名称和按压反馈。
- 筛选、口味、单位和行政区选项提供明确的选中状态说明。
- 图标和箭头等装饰内容从辅助信息中隐藏。
- 删除、清理等危险操作继续保留二次确认。

### 2.2 表单可访问性

- 为 `input`、`textarea`、`slider` 和 `picker` 增加明确的可访问名称。
- 为输入控件增加稳定的 `id`、`name`、正确输入类型和必要的输入模式。
- 必填项使用一致的文字说明，不只依赖星号表达。
- 提交期间禁用提交按钮，避免重复操作。
- 加载、校验失败和提交结果提供可感知状态。
- 用户存在未提交内容时，不改变现有草稿保存逻辑。

### 2.3 触控与视觉反馈

- 交互目标的最小高度按移动端触控习惯调整，不保留只有文字大小的点击区域。
- 主按钮、次级按钮、卡片、筛选项和危险操作提供一致的按压反馈。
- 避免 `transition: all`，只声明需要动画的属性。
- 弹层限制滚动穿透，并保留底部安全区。
- 对支持减少动态效果的环境停用非必要动画。

### 2.4 排版与颜色

- 提升正文辅助色和状态标签的文字对比度。
- 将过小的全局字号提升到可读下限。
- 长菜名、投稿名称、推荐理由和用户输入内容支持换行或截断，避免横向溢出。
- 数字、金额和列表字段保持稳定对齐。
- 加载文案统一使用中文省略号“…”而不是三个英文句点。

### 2.5 状态与性能

- 加载、空数据、错误和异步结果区域增加可感知状态提示。
- 长历史、食材和投稿列表避免一次渲染无上限内容；本轮优先采用小程序支持的列表滚动能力，不引入第三方虚拟列表库。
- 不增加图片、字体或新的远程资源。

## 3. 主要修改位置

- `miniprogram/app.wxss`：颜色、字号、按钮和通用交互状态。
- `pages/index`：候选卡片、评分弹层、条件选择和加载状态。
- `pages/pantry`：编辑删除操作、食材表单和选项触控区域。
- `pages/profile`、`pages/history`、`pages/data-manage`：导航和筛选语义。
- `pages/submission`、`pages/admin-review`：表单名称、提交状态和错误可感知性。
- `pages/shopping-list`：复选操作、删除操作和手动添加表单。
- `pages/recipe-detail`、`pages/delivery-detail`：长文本、加载状态和底部操作区。
- `components/district-picker`：弹层语义、行政区选中状态和滚动隔离。

## 4. 不在本次范围

- 不重新设计品牌、配色方向或页面信息架构。
- 不增加新业务功能。
- 不修改推荐算法、数据模型和云端接口。
- 不引入 UI 组件库。
- 不为网页键盘快捷键和 URL 深链接强行套用不适用于微信小程序的规则。
- 不承诺修复微信开发者工具或基础库自身的辅助功能限制。

## 5. 兼容策略

Web Guidelines 中依赖 HTML、浏览器 URL、SSR 或 ARIA DOM 的规则，需要按微信小程序能力适配：

- HTML `aria-label` 对应小程序支持的 `aria-label` / `aria-role`。
- HTML 链接语义对应小程序导航按钮或具备导航角色的交互卡片。
- 浏览器 `prefers-reduced-motion` 只在 WXSS 支持时启用，不能影响基础交互。
- URL 状态、Hydration、`autocomplete` 和网页图片加载规则不机械应用到无对应能力的小程序页面。

## 6. 验证方式

实施后执行：

1. 运行现有 TypeScript 类型检查和自动化测试。
2. 扫描残留的可点击 `view/text`、无名称表单、`transition: all` 和英文三点省略号。
3. 检查所有修改文件的格式与差异。
4. 在微信开发者工具中编译并检查主要页面。
5. 对首页、食材、历史、投稿、审核和数据清理执行核心交互冒烟测试。
6. 在窄屏和带底部安全区的设备尺寸下检查长文本与固定操作栏。

## 7. 验收标准

- 简单操作不再依赖无语义的 `text` 点击区域。
- 所有可编辑表单控件具有明确可访问名称。
- 所有主要触控目标具备可见按压反馈和合理尺寸。
- 异步加载和提交状态可被用户识别。
- 页面不存在 `transition: all`。
- 非必要动画具备减少动态效果的降级方式。
- 低对比度辅助文字和过小字号得到统一修正。
- 长文本不导致横向溢出或操作按钮被挤出屏幕。
- 页面业务行为和导航路径保持不变。
